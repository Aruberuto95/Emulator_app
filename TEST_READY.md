# Test Readiness Manifest: Universal GBC and GBA Emulator

This manifest tracks the verification status and provides instructions for executing the End-to-End (E2E) test suite of the Universal GBC and GBA Emulator.

---

## 1. System Requirements & Setup
- **Operating System**: macOS (macOS 13.0 or later recommended)
- **Rust Toolchain**: `rustc` / `cargo` (1.70.0 or later)
- **CMake**: version 3.20 or later
- **Dependencies**: SDL2 (install via `brew install sdl2`)
- **Python**: Python 3.10+ (with `pytest`)

---

## 2. Compilation and Build Commands (Resource-Safe)
Verify that the hybrid workspace compiles cleanly. Note that compilation concurrency must be limited to a maximum of 2 jobs:
```bash
# Configure the build with CMake
cmake -B build -S . -DCMAKE_BUILD_TYPE=Debug

# Compile all targets with concurrency limit (max 2 jobs)
cmake --build build -j 2
```
*Acceptance Criteria*: Compilation completes without warnings, and C++ header files generated by `cxx` are correctly included.

## 5. Executing the Test Suite
Run the full suite using Python's `pytest` framework:
```bash
# Run all tests (E2E and Adversarial)
pytest tests/
```
*Acceptance Criteria*: All 99 tests pass cleanly (output exit code 0) in under 8 seconds.

---

## 6. Resource Safety Guidelines
1. **Compilation Concurrency Limit**: Cargo and CMake builds must limit concurrency to at most 2 parallel jobs (e.g. `cmake --build build -j 2`).
2. **Strict Timeouts**: All python subprocess spawning and pytest command executions must specify explicit timeouts (e.g. `timeout=10.0`).
3. **CPU Interpreter Safeguards**: Rust CPU interpreters and mock cores must implement execution limit checks and cycle threshold safeguards to prevent loops.
