# Project: Universal GBC and GBA Emulator

## Architecture
This project implements a high-performance Game Boy Color (GBC) and Game Boy Advance (GBA) emulator with a Rust backend (core) and a C++ frontend (SDL2) communicating via a zero-copy FFI boundary generated by `cxx`.

```
                  +--------------------------------+
                  |          C++ Frontend          |
                  |     (SDL2 Event Loop & I/O)    |
                  +---------------+----------------+
                                  |
                   FFI Bridge     | (Zero-copy Buffers & Control)
                  (cxx::bridge)   |
                                  v
                  +---------------+----------------+
                  |           Rust Core            |
                  |  (GBC Core / GBA Core / MMU)   |
                  +--------------------------------+
```

### Key Modules:
1. **Root Build Configuration**: A top-level CMake configuration linking Cargo-based Rust build and C++ frontend build.
2. **Rust Core (`emulator_core`)**:
   - ROM parsing and validation (Nintendo logo, checksums, safety traversal checks).
   - Sharp LR35902 CPU interpreter (GBC) and ARM7TDMI CPU interpreter (GBA).
   - MMU and memory bank controllers (MBC3 + RTC for GBC, EWRAM/IWRAM/Flash 128KB for GBA).
   - Precise timing, interrupts, and DMA controllers.
   - PPU (Mode 0 tiled backgrounds, sprites, palettes).
   - APU & Audio resampling.
   - State serialization.
3. **C++ Frontend**:
   - SDL2 setup, dynamic window scaling based on active console type (GBC: 160x144, GBA: 240x160).
   - Main event loop with speed multiplier support, input injection, and zero-copy rendering.

## Interface Contracts
The FFI boundary is defined using `cxx::bridge`.

### Rust Types Exposed to C++
- `struct ButtonState`: Containing digital button inputs (UP, DOWN, LEFT, RIGHT, A, B, L, R, START, SELECT).
- `enum ConsoleType`: `GBC` or `GBA`.
- `struct RomInfo`: Exposing ROM name, console type, and validation status.
- Opaque type `Emulator` representing the emulator instance.

### FFI Functions (in C++ namespace `ffi`)
- `std::unique_ptr<Emulator> create_emulator()`: Initializes a fresh emulator instance.
- `bool load_rom(Emulator& emu, rust::Slice<const uint8_t> rom_data)`: Validates and loads a ROM, initializing the core.
- `void play(Emulator& emu)`: Starts/resumes emulator execution.
- `void pause(Emulator& emu)`: Pauses emulator execution.
- `void reset(Emulator& emu)`: Resets emulator state.
- `void tick(Emulator& emu)`: Executes emulator frames for the active step.
- `void inject_input(Emulator& emu, ButtonState buttons)`: Passes controller inputs.
- `rust::Slice<const uint16_t> get_video_buffer(const Emulator& emu)`: Zero-copy video buffer slice in BGR555 (XBGR1555) pixels; invalidated by the next `tick()`. The `DUMP_VIDEO` command still writes RGB888 to disk.
- `rust::Slice<const int16_t> get_audio_buffer(const Emulator& emu)`: Zero-copy audio buffer slice.
- `void set_speed(Emulator& emu, float speed)`: Sets emulator speed multiplier.
- `bool save_state(Emulator& emu, uint8_t slot)`: Saves emulator state atomically to a file.
- `bool load_state(Emulator& emu, uint8_t slot)`: Loads emulator state.
- `ConsoleType get_console_type(const Emulator& emu)`: Returns the active console type.

## Code Layout
- `CMakeLists.txt` - Root CMake configuration.
- `Cargo.toml` - Root Cargo configuration.
- `core/` - Rust crate folder.
  - `Cargo.toml`
  - `src/lib.rs` - Library entry point, FFI `cxx::bridge` block.
  - `src/gbc/` - Game Boy Color core module.
  - `src/gba/` - Game Boy Advance core module.
  - `src/rom.rs` - Safe ROM scanning, parsing, validation, path traversal check.
  - `src/resampler.rs` - Audio resampling logic.
  - `src/savestate.rs` - Atomic state serialization.
- `frontend/` - C++ application folder.
  - `CMakeLists.txt`
  - `src/main.cpp` - SDL2 bootstrap, event loop, and FFI interaction.
- `tests/` - E2E tests folder.
